# 패턴별 구현 플레이북

아래 항목은 구현 제안과 검증 조건이다. 실제 관찰은 [라이브러리 인덱스](library-index.md)에서 필요한 사이트 문서를 선택해 읽는다. 검색어가 아닌 실제 이미지 구조로 패턴을 고른다.

## SaaS·개발자 랜딩

태그: `saas-landing`, `developer-landing`, `conversion-cta`, `features`.

- 좌우 분할형, 중앙 집중형, 미디어 배경형 중 주 레퍼런스의 실루엣을 고른다. 모든 결과를 중앙 제목과 카드 세 장으로 통일하지 않는다.
- 제목의 줄 수와 폭, CTA 개수, 제품 캡처 또는 일러스트의 비중을 명세로 확정한다.
- 이메일 입력 CTA는 입력 검증과 다음 가입 화면으로 연결한다. 단순 시작 CTA는 사용자의 제품 시작 경로로 연결한다.
- 기능 목록은 행·캐러셀·텍스트 격자 중 관찰된 형태를 따른다. 캐러셀의 이동·끝 상태·키보드 접근을 구현한다.
- 완료 조건: 가입 진입과 기능 탐색이 동작하며 첫 화면의 영역 비율을 원본과 비교했다.

## 커머스·상품 상세

태그: `commerce-landing`, `commerce`, `product-detail`, `wishlist`, `product-picker`, `quantity-selector`.

- 사진 중심의 브랜드 랜딩과 상품 구매 UI를 구분한다. 사진만 있는 히어로에서 원본에 없는 가격·CTA가 관찰됐다고 기록하지 않는다.
- 상세 페이지는 갤러리, 옵션, 재고, 수량, 구매 방식, 가격, 장바구니를 일관된 상품 데이터로 연결한다.
- 일회성/구독 선택에 따라 표시 가격·합계가 함께 바뀐다. 필수 옵션이 빠졌으면 구매 버튼 근처에 오류를 표시한다.
- 저장과 장바구니를 구분하고 중복 추가·수량 최소값·품절·빈 장바구니를 처리한다.
- 완료 조건: 상품 선택 → 옵션 → 수량 → 담기 → 장바구니의 합계가 맞는다.

## 대시보드·표·작업 관리

태그: `dashboard`, `task-management`, `task-table`, `task-log`, `skill-management`, `service-catalog`.

- 사이드바, 목록, 상세 패널의 개수와 폭을 관찰대로 유지한다. 통계 차트가 없는 화면에 차트를 기본 삽입하지 않는다.
- 행 선택과 상세 데이터, 상태 편집과 목록 칩, 생성과 검색 결과를 동기화한다.
- 정렬은 숫자·날짜·문자형에 맞게 수행하고 필터 초기화와 빈 결과를 제공한다.
- 스킬 토글·서비스 추가·작업 상태 등 화면 유형에 맞는 행동만 연결한다.
- 완료 조건: 검색·필터·정렬·선택·편집을 연달아 사용해도 목록과 상세가 일치한다.

## 금융·청구·구독

태그: `finance`, `billing`, `subscription`, `pricing`.

- 금액, 통화, 기간, 자산과 부채를 분리한다. 차트·합계·거래 목록은 같은 데이터 소스를 사용한다.
- 기간 선택에 따라 합계와 그래프를 갱신하고 날짜 범위를 검증한다.
- 요금표 월/연 토글은 숫자뿐 아니라 청구 주기·할인·좌석당 단위를 바꾼다. 기본료+좌석료 구조는 한 가격으로 뭉개지 않는다.
- 플랜 선택 → 청구 정보 → 데모 완료 상태의 흐름을 구성한다. 저장되는 폼에는 실제 카드번호를 사용하지 않는다.
- 완료 조건: 플랜·좌석·청구 주기의 합계가 맞고 완료 후 현재 플랜 요약이 갱신된다.

## 검색·필터·디렉터리·채용

태그: `search-filter`, `directory`, `recruitment`, `product-search`.

- 결과 카드, 결과 표, 상세 패널 중 관찰된 구조를 선택한다. 회사 디렉터리와 숙소 검색을 같은 것으로 분류하지 않는다.
- 검색 문자열·선택 필터·정렬·페이지를 하나의 상태로 관리한다. 필터 변경 시 결과 수와 페이지를 갱신한다.
- 계층형 필터는 부모/자식 팝오버의 닫기·포커스·선택 상태를 처리한다.
- 지도는 도구/API가 있으면 연결한다. 지도 이미지 데모는 실제 지도 동작으로 설명하지 않는다.
- 완료 조건: 다중 필터 → 결과 없음 → 초기화 → 상세 → 복귀 과정에서 선택 상태가 유지된다.

## 여행·예약·식당·이벤트

태그: `travel`, `booking`, `property-catalog`, `event-catalog`, `restaurant-search`, `restaurant-brand`, `restaurant-admin`.

- 브랜드 소개, 사용자 예약, 운영자 메뉴 관리 세 용도를 구분한다.
- 예약은 날짜·인원·가격·선택 대상이 다음 단계와 주문 요약에 함께 전달되도록 구현한다.
- 체크아웃은 예약 요청·승인 대기·확정을 서로 다른 상태로 표현한다. 대기 화면을 최종 확정으로 바꾸지 않는다.
- 음식점 검색은 날짜·시간·인원과 지역을 연결한다. 관리자 메뉴는 품목 추가·가격·재고·카테고리 편집을 연결한다.
- 완료 조건: 잘못된 날짜·인원에 오류가 나타나고, 뒤로 이동 후에도 예약 내용이 보존된다.

## 학습·미디어·문서·자산 라이브러리

태그: `learning`, `course-detail`, `media-library`, `asset-library`, `document-library`, `project-library`.

- 이미지 그리드 모양만 보고 강좌·음악·문서·프로젝트를 혼동하지 않는다. 실제 제목·도구·탭을 확인한다.
- 카드 → 상세 → 목록 복귀를 연결하고 검색·유형·날짜 필터와 그리드/목록 전환을 같은 데이터에 적용한다.
- 강좌는 챕터·강의 선택·진도 상태를, 음악은 트랙 선택과 재생 상태를, 자산은 상세와 유형 필터를 구현한다.
- 실제 재생 소스가 없으면 재생 버튼이 데모 상태만 바꾼다는 점을 밝힌다.
- 완료 조건: 선택 콘텐츠의 상세와 목록이 일치하고 빈 라이브러리에서도 추가 행동이 가능하다.

## 포트폴리오·건축·편집 콘텐츠

태그: `portfolio`, `property-editorial`, `editorial`, `typography`, `image-collage`.

- 큰 미디어, 비대칭 이미지, 콜라주, 텍스트 중심 등 레퍼런스의 구조를 유지한다.
- 제목의 실제 줄바꿈·이미지 crop·캡션·읽기 폭·그리드 비율을 명세로 정한다.
- 프로젝트나 기사 카드는 상세로 이동하고 카테고리·최근 글·관련 글을 데이터로 연결한다.
- 빈 미디어 또는 어두운 전환 프레임만 보이는 자료는 `needs-review`로 두고 주요 레퍼런스로 자동 선택하지 않는다.
- 완료 조건: 작품·글 탐색이 가능하고 에셋 교체 후에도 영역 비율과 텍스트 대비가 유지된다.

## 팀·미션·고객 후기

태그: `team-about`, `mission-about`, `testimonials`.

- 팀 사진 그리드, 단체 사진, 이미지 모자이크를 구분한다. 후기의 사진·인용·직책·출처를 함께 관리한다.
- 후기 캐러셀은 원본에 컨트롤이 보이면 이동·진행 표시를 연결한다. 정적 캡처만으로 자동 재생을 추정하지 않는다.
- 미션 문구를 사용자 조직의 내용으로 바꾸고 실제 고객처럼 보이는 허구 후기·로고는 샘플임을 표시한다.
- 완료 조건: 팀 상세·후기 이동·관련 CTA가 동작하고 모바일에서 순서와 읽기 폭이 자연스럽다.

## 문의·FAQ·푸터·뉴스레터

태그: `contact-form`, `faq`, `footer`, `newsletter`.

- 폼은 레이블·필수값·이메일 검증·동의·제출 중·성공·실패를 처리한다. 서버가 없으면 데모 접수 상태를 표시한다.
- FAQ는 활성 상태·펼침 내용·아이콘이 일치하고 `aria-expanded` 및 키보드 조작이 가능하게 구현한다.
- 뉴스레터와 문의를 다른 성공 상태로 연결한다. 푸터 링크는 실제 페이지 또는 설명 가능한 데모 경로로 연결한다.
- 완료 조건: 유효하지 않은 제출은 막히고 성공 후 중복 제출이 방지된다.

## 가입·온보딩·에디터·게시

태그: `authentication`, `onboarding`, `workspace`, `editor`, `publishing`.

- 이메일 입력·인증 대기·인증 완료·프로필·워크스페이스 등 단계별 상태를 분리한다.
- 원본 흐름의 직접 확인된 단계와 확인하지 않은 단계를 구분한다. 부분 프리뷰만으로 전체 전환을 사실로 확정하지 않는다.
- 초대는 이메일 검증·행 추가·건너뛰기·완료를, 게시물은 제목·본문·초안·미리보기·게시 후 상세를 구현한다.
- 게시 전후 레이아웃의 차이와 편집 복귀를 유지한다.
- 완료 조건: 단계 검증·되돌아가기·완료 상태가 동작하며 실제 계정 생성이나 게시 여부가 명확하다.
